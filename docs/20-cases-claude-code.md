2026년 7월 20일부터 24일까지 나흘간 4번의 연속 릴리스로 각각 다른 격리 경계가
닫혔다. 이 압축된 릴리스 열은 AGENTFENCE의 출발점이 된 관찰이다.

> **W1-2 정정 (2026-08-01).** 아래 표는 원래 2차 출처(블로그)에 근거했고
> 버전 귀속에 오류가 있었다. 공식 CHANGELOG로 교차 확인해 정정했다.
> 정정 내역은 `../LOG.md` W1-2 항목 참조.

| 버전 | 경계 | 항목 (CHANGELOG 원문 근거) |
|---|---|---|
| 2.1.216 | B1 | worktree 격리 서브에이전트가 `git -C` · `--git-dir` · `GIT_DIR`/`GIT_WORK_TREE`로 공유 체크아웃에 git을 리다이렉트하던 문제 수정 |
| 2.1.216 | B1 | 작업 디렉터리가 일치하지 않을 때 worktree 세션이 다른 프로젝트의 남은 worktree에 안착하던 문제 수정 |
| 2.1.216 | — | `sandbox.filesystem.disabled` 설정 추가 (네트워크 egress 제어는 유지한 채 파일시스템 격리만 건너뜀) |
| 2.1.217 | B1 | 백그라운드 세션 격리가 심볼릭 링크된 작업 디렉터리를 정규화하지 않아 세션이 워크스페이스 밖으로 탈출할 수 있던 문제 수정 |
| 2.1.218 | — | Windows `\u` 접두 경로 손상 수정. **보안 경계와 무관** |
| 2.1.219 | B2 | `sandbox.network.strictAllowlist` 설정 추가 — 비allowlist 호스트를 프롬프트 없이 거부 |

**정정된 것 세 가지.**

1. git worktree 리다이렉션과 낡은 worktree 부착은 2.1.218이 아니라 **2.1.216**이다.
2. 2.1.218은 Windows 경로 인코딩 수정이고 **보안 항목이 아니다.**
3. `/rewind`가 링크를 따라가 파일을 삭제했다는 항목은 **CHANGELOG에서 확인되지 않는다.**
   2차 출처에만 있으므로 케이스로 채택하지 않는다.

날짜(7/20~7/24)도 2차 출처 값이라 CHANGELOG로 확인되지 않았다. 버전 번호만 쓴다.

## AGENTFENCE 관점의 함의

같은 경계(B1)가 사흘 동안 세 가지 다른 경로로 뚫렸다. 개별 수정은 각각의
경로를 막았지만, 경로가 아니라 **경계 단위로 회귀를 확인하는 테스트**가
없다는 것이 구조적 공백이다. 케이스는 "이 CVE가 재현되는가"가 아니라
"이 경계를 넘을 수 있는가"로 작성해야 한다.
